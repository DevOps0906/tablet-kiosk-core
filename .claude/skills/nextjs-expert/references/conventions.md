# nextjs-expert — conventions

> 작성 시점 기준 일반 규약. 프로젝트의 실제 버전 · 기존 코드가 우선한다. 불일치는 보고한다.

## 라우트

- `app/` 아래 폴더 = 경로. 화면 목록은 `apps/admin/CLAUDE.md` "화면 (1차)" 표를 따른다 (`/login`, `/coupons`, `/coupons/new` …).
- 로그인 필요 영역과 공개 영역(`/login`)은 라우트 그룹으로 분리한다.
- 로딩 · 에러 경계는 라우트 단위로 둔다.

## 서버/클라이언트 경계

- 기본은 서버 컴포넌트. `"use client"`는 이벤트 · 상태 · 브라우저 API 가 필요한 최소 컴포넌트에만.
- 서버에서 클라이언트로 넘기는 props 는 직렬화 가능한 값만.
- 서버 전용 모듈(비밀 · DB)을 클라이언트 모듈에서 import 하지 않는다.

## 인증 세션 (Supabase)

- 쿠키 기반 세션 클라이언트를 서버/브라우저용으로 구분해 만든다 (`@supabase/ssr` — 팩토리 이름은 버전 확인).
- 보호 라우트 판단은 서버에서 한다. 클라이언트 상태만으로 보호하지 않는다.
- 사장님은 자기 매장(`store_id`)만 본다. 화면 필터가 아니라 RLS 가 막아야 한다.

## 서버 호출

- 쿠폰 발행처럼 service role 이 필요한 일은 Edge Function 을 부른다 (`docs/06` 함수 표). 대시보드가 service role 키를 갖지 않는다.
- 응답은 타입으로 좁히고, 오류 응답을 한 곳에서 화면 문구로 바꾼다.
- 계약 정본은 `docs/06` · `docs/07`과 `supabase/` 코드다. 필드를 추정하지 않는다.

## 반응형

- 구간: 모바일 ≤767px · 태블릿 768–1199px · 데스크탑 ≥1200px.
- 글자 크기 · 여백은 `apps/admin/CLAUDE.md` 표의 CSS 변수(`--fs-h1` 등)로만.
- 업종 테마 색은 로그인한 매장의 `vertical`에 따라 CSS 변수로 바꾼다 (`DESIGN.md` 3장).
