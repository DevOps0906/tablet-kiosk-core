# 05 출력 — 주문서 · 영수증

> 위치: `apps/kiosk/lib/core/printing/`. 기기 전송은 `kiosk_devices.ReceiptPrinter`.

## 1. 출력물 종류

| 출력물 | 받는 곳 | 시점 | 업종 확장 |
|---|---|---|---|
| 주방 주문서 | 주방 프린터 (없으면 영수증 프린터) | 주문 확정 즉시 | 식당: 분류별로 나눠 출력 / 카페: 바리스타용 옵션 강조 / 버거: 재료 변경 강조 |
| 고객 영수증 | 카운터 프린터 | 주문 확정 즉시 | 카페: 스탬프 현황 줄 |
| 호출표 / 번호표 | 카운터 프린터 | 영수증 아래 | 버거: 주문번호 크게 |
| 취소 영수증 | 카운터 프린터 | 승인 취소 시 | — |
| 테스트 출력 | 선택한 프린터 | 세팅 4단계 | — |

## 2. 양식 구조 (80mm, 한 줄 48칸)

양식은 **블록 목록**으로 만든 뒤 ESC/POS 바이트로 바꿉니다. 업종 모듈은 블록을 추가 · 교체만 합니다.

```
[헤더]        가게 이름 · 기기 이름 · 출력 시각
[주문유형]    ★ 매장 ★  또는  ★ 포장 ★        ← 가로 · 세로 2배 크기, 반전 인쇄
[번호]        호출번호 / 주문번호  (2배 크기)
[항목들]      메뉴명 x 수량                  금액
              └ 옵션 · 변경 (들여쓰기)
[할인]        쿠폰명                       -5,000원
[합계]        결제 금액                    67,000원
[결제]        카드 승인 2건 (더치페이 N등분)
[업종 블록]   (업종 모듈이 추가)
[푸터]        안내 문구 · 다음 방문 쿠폰(영수증 하단 인쇄 쿠폰 발행 시)
[자르기]
```

- **매장 / 포장 표시는 모든 주방 주문서에 반드시 가장 크게** 인쇄합니다. (요구사항)
- 주방 주문서에는 금액을 빼고 메뉴 · 수량 · 옵션만 크게 인쇄합니다. (설정으로 금액 표시 가능)
- 한글은 2칸으로 계산해 줄을 맞춥니다. 긴 메뉴명은 다음 줄로 넘깁니다.

## 3. 출력 대기열

| 항목 | 규칙 |
|---|---|
| 저장 | drift `print_jobs` (주문 ID, 출력물 종류, 프린터, 바이트 또는 양식 데이터, 시도 횟수, 상태) |
| 순서 | 주문 확정 → 출력 작업 생성 → 즉시 1회 시도 |
| 실패 | 3회까지 자동 재시도 (2초 · 5초 · 15초), 이후 `failed`로 대기 |
| 표시 | 손님 화면에는 표시하지 않음. 사장님 PIN 화면 · 상단 작은 배지 "출력 대기 N건" |
| 재출력 | 사장님 화면에서 건별 / 전체 재출력, 다른 프린터로 보내기 |
| 중복 | 같은 주문서 재출력 시 머리에 `[재출력]` 표시 |

## 4. 바이트 생성 규칙

- ESC/POS 명령 중 사용하는 것: 초기화, 정렬, 굵게, 글자 크기(가로 · 세로 배수), 반전, 줄바꿈, 용지 자르기, (선택) 바코드 · QR.
- 한글 인코딩 1순위: CP949(EUC-KR) + 프린터 한글 모드. 지원하지 않는 기종은 양식을 이미지로 그려 래스터 명령으로 보냅니다.
- 프린터 기종별 차이(코드페이지 번호, 자르기 명령)는 **프린터 프로필**로 분리합니다. 기본 프로필 + 시범 매장 기종 프로필부터 시작.

## 5. 가짜 프린터 (윈도우 개발)

- 미리보기 창: 80mm 폭으로 양식을 그려 보여 줌 (2배 크기 · 반전도 흉내)
- `build/print-logs/<주문ID>-<종류>.bin`에 실제 바이트 저장 → 나중에 실제 프린터로 그대로 보내 비교 가능

## 6. 테스트

- 매장 / 포장이 모든 주방 주문서 상단에 크게 나오는지
- 메뉴명 20자 이상, 옵션 5개 이상일 때 줄바꿈
- 프린터 전원 끔 → 대기열 → 전원 켬 → 재출력
- 주방 프린터 없음 설정 → 영수증 프린터로 주방 주문서 + 영수증 순서 출력
