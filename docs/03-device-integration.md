# 03 기기 연동

> 위치: `packages/kiosk_devices/`. 앱 코드는 아래 **인터페이스만** 압니다.

## 1. 인터페이스 (설계)

| 인터페이스 | 주요 동작 | 진짜 구현 | 가짜 구현 |
|---|---|---|---|
| `CardTerminal` | `connect()`, `status`, `approve(amount, idempotencyKey)`, `cancel(approvalNo, amount)` | VAN SDK / 앱투앱 (Kotlin 플랫폼 채널) | 개발 도구 대화상자로 결과 선택 |
| `ReceiptPrinter` | `discover()`, `connect(address)`, `printBytes(bytes)`, `status` | TCP 9100 소켓 (LAN · 와이파이) | 미리보기 창 + 파일 저장 |
| `BarcodeInput` | `stream<String> scans` | USB · 블루투스 HID 스캐너(키보드 입력 수집) + 카메라 | 개발 도구 입력란 |
| `KioskLock` | `enter()`, `exit(pin)`, `isLocked` | Android Lock Task | 배지 표시만 |

모든 동작은 **결과 타입**으로 성공 / 실패 이유를 돌려줍니다. 예외를 화면까지 던지지 않습니다.

```
ApproveResult
  ├─ Approved(approvalNo, maskedCard, amount, approvedAt, terminalId)
  ├─ Declined(reasonCode, message)       // 한도 초과, 거래 정지 등
  ├─ Timeout                             // 손님이 카드를 안 댐
  └─ CommError(message)                  // 단말 · VAN 통신 오류 → 승인 여부 불명확
```

`CommError`는 **승인되었는지 알 수 없는 상태**입니다. 같은 멱등 키로 상태 조회 / 망취소를 먼저 시도하고, 확인이 안 되면 직원 호출로 넘깁니다. (`docs/04` 4장)

## 2. 카드 단말 (VAN)

| 항목 | 내용 |
|---|---|
| 계약 | 매장(사업자)이 VAN사와 가맹 계약. 우리는 VAN사의 연동 규격을 따름 |
| 단말 | 여신금융협회 인증을 받은 단말만 사용 (스탠드 일체형 / 블루투스 리더) |
| 연동 방식 A — SDK | VAN사가 주는 안드로이드 라이브러리(AAR)를 `kiosk_devices`의 Kotlin 쪽에 넣고 플랫폼 채널로 호출 |
| 연동 방식 B — 앱투앱 | 태블릿에 VAN사 결제 앱을 설치하고 Intent로 호출 → 결과를 돌려받음 |
| 우리가 저장하는 것 | 승인번호, 승인 일시, 마스킹 카드번호, 카드사명, 금액, 단말 ID |
| **저장 금지** | 카드번호 전체, 유효기간, 트랙 데이터 등 카드 정보 일체 |
| 결정 | VAN사 미정 → `docs/00` D1. 시범 매장이 쓰는 VAN사 문서를 받은 뒤 task-017 진행 |

## 3. 프린터 (ESC/POS)

| 항목 | 내용 |
|---|---|
| 1차 지원 | LAN · 와이파이 프린터, TCP 포트 9100으로 ESC/POS 바이트 전송 |
| 용지 | 80mm (한 줄 48자 기준, 한글은 2칸) / 58mm는 설정으로 |
| 한글 | 프린터 한글 모드 + CP949(EUC-KR) 인코딩이 1순위. 프린터가 지원하지 않으면 **이미지(래스터) 출력**으로 대체 |
| 인코딩 패키지 | ESC/POS 명령은 단순하므로 `core/printing`에 직접 작성 (기존 패키지는 유지보수가 오래 멈춘 것이 많음, 사용 시 최근 업데이트 확인) |
| 프린터 찾기 | 같은 네트워크에서 9100 포트 검색 + IP 직접 입력 |
| 상태 확인 | 연결 실패 / 시간 초과만 판단 (용지 없음 감지는 기종별 → 2차) |
| 2차 | 블루투스 프린터 — 영수증 프린터는 블루투스 클래식(SPP)이 많아 BLE 전용 패키지로는 안 될 수 있음. 기종 확인 후 진행 (`docs/00` D7) |
| 주방 프린터 없을 때 | 영수증 프린터 하나로 주방 주문서 + 영수증을 이어서 출력 (세팅 4단계 안내 문구와 동일) |

양식과 대기열은 `docs/05-printing.md`.

## 4. 바코드 · QR

| 입력 | 방식 | 비고 |
|---|---|---|
| USB · 블루투스 스캐너 | 키보드처럼 문자를 보내고 Enter로 끝남 → 짧은 시간 안에 들어온 연속 입력을 스캔으로 판단 | 스탠드형 기본. 윈도우에서도 테스트 가능 |
| 카메라 | `mobile_scanner` (Code128 · QR) | 갤럭시탭형. 앞면 카메라 선택 |

스캔 값은 쿠폰 시리얼 형식(`XXXX-XXXX-XXXX`, 하이픈 없이 12자도 허용)으로 정규화한 뒤 `core/coupon`에 넘깁니다.

## 5. 키오스크 잠금

| 단계 | 방법 |
|---|---|
| 개발 | 화면 고정(Screen Pinning) — 손님이 해제 방법을 알 수 있어 운영용 아님 |
| 운영 | **Lock Task 모드** — 앱을 Device Owner로 지정해야 완전 잠금 |
| Device Owner 지정 | 초기화 직후(계정 없는 상태) 태블릿에서 `adb shell dpm set-device-owner <패키지>/<관리자 리시버>` 실행. 설치 가이드 문서로 제공 |
| 대안 | Samsung Knox 기반 키오스크 관리 (유료, 대량 설치 시 검토) |
| 해제 | 화면 구석 5번 탭 → 사장님 PIN 입력 → 세팅 화면 |
| 자동 실행 | 태블릿 재부팅 시 앱 자동 실행 + 잠금 재진입 |
| 화면 꺼짐 방지 | 영업 중 화면 항상 켜짐, 일정 시간 무입력 시 시작 화면으로 |

## 6. 기기 상태 표시

- 갤럭시탭형 손님 화면 상단: "카드 리더 연결됨 · 프린터 정상" (디자인 `sw-*-pay`)
- 기기 문제 발생 시 손님 화면은 결제 시작을 막고 "직원을 호출해 주세요" 안내
- 사장님 세팅 4단계(`set-04-devices`)에서 연결 · 테스트 결제(바로 취소) · 테스트 출력
