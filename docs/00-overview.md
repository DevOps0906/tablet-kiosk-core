# 00 개요 — 린 검증 게이트 · 용어 · 결정 대기

## 1. 린 검증 게이트 (개발 착수 조건)

`tasks/`의 Phase 2(손님 주문) 이후 작업은 아래 조건을 채운 뒤 시작합니다. Phase 1(기반)은 검증과 병행할 수 있습니다.

| # | 조건 | 방법 | 상태 |
|---|---|---|---|
| G1 | 개인 매장 사장님 10명 인터뷰 | 설계 저장소 `screenshots/` PNG로 화면을 보여주며 인터뷰 | 대기 |
| G2 | "월 구독으로 쓰겠다" 3명 이상 | 인터뷰 마지막에 가격 제시 (예: 월 정액) 후 의향 확인 | 대기 |
| G3 | 시범 매장 1곳 확보 (카페 우선) | 무료 시범 사용 약속 | 대기 |
| G4 | VAN사 1곳 연동 조건 확인 | 아래 결정 대기 D1 | 대기 |

인터뷰에서 꼭 물어볼 것:
- 지금 주문 · 결제는 어떻게 받고, 무엇이 가장 불편한가
- 갖고 있는 태블릿 · 프린터 · 카드 단말 기종
- 더치페이 요청이 얼마나 자주 있는가
- 쿠폰 · 스탬프를 지금 어떻게 하고 있는가 (종이 쿠폰? 앱?)
- 월 얼마면 쓰겠는가

## 2. 용어집

| 용어 | 뜻 |
|---|---|
| 하드웨어 설치형 / 스탠드형 | 스탠드 + 카드 단말 + 프린터 일체 세트, 세로 800×1280 |
| 소프트웨어 설치형 / 갤럭시탭형 | 매장 태블릿에 앱만 설치, 가로 1280×800 |
| 업종 모듈 (vertical) | 식당 · 카페 · 버거별 기능을 끼우는 코드 단위 (`docs/08`) |
| 업종 프리셋 | 업종 선택 시 함께 들어가는 기본 분류 · 메뉴 예시 · 문구 |
| 주문 세션 | 시작 화면에서 매장/포장을 고른 순간부터 완료 화면까지 |
| 결제 건 (payment) | 카드 승인 1회. 더치페이는 주문 1건에 결제 건 여러 개 |
| 멱등 키 | 같은 결제 요청을 두 번 보내도 한 번만 승인되게 하는 고유 값 |
| VAN | 카드 승인을 카드사로 중계하는 사업자 (계약 필요) |
| ESC/POS | 영수증 프린터 명령 표준 |
| 출력 대기열 (print queue) | 출력 실패한 주문서를 다시 보내기 위해 쌓아 두는 목록 |
| 가짜 기기 모드 (fake) | 실제 기기 없이 결제 · 출력 · 스캔을 흉내 내는 개발용 모드 |
| 키오스크 잠금 | 손님이 앱을 벗어나지 못하게 하는 안드로이드 Lock Task 모드 |

## 3. 결정 대기 목록

| # | 결정할 것 | 선택지 | 영향 받는 작업 |
|---|---|---|---|
| D1 | VAN사 · 카드 단말 | 시범 매장이 쓰는 VAN사 우선 확인 → SDK 방식 / 앱투앱 방식 | task-017 |
| D2 | 사장님 로그인 방식 | 디자인(`set-01-start`)은 **휴대폰 번호 인증** — 문자 인증 서비스 선택 필요 / 대안: 이메일 · 카카오 | task-005, task-014 |
| D3 | 기기 등록 방식 | 매장 코드 6자리 입력 / QR | task-014 |
| D4 | 쿠폰 할인과 더치페이 | **안 A (권장)**: 쿠폰은 결제 방법 선택 전에 총액에서 빼고, 분할은 할인 후 금액 기준 / 안 B: 디자인 플로우차트 문구대로 첫 결제 건에서 차감 | task-018, task-021 |
| D5 | 월 구독 가격 · 결제 수단 | 인터뷰(G2) 결과로 결정 | 대시보드 결제 페이지 (범위 밖) |
| D6 | 스탠드 하드웨어 공급처 | 스탠드 · 일체형 단말 공급사 견적 비교 | task-025 |
| D7 | 블루투스 프린터 지원 시점 | MVP 제외(LAN만) / 포함 | task-016 |
| D8 | 다국어(English) 지원 시점 | 시작 화면 디자인에 `한국어 · English` 버튼이 있음 → MVP는 숨김(권장) / 포함 | task-007 |

결정되면 이 표에 결과와 날짜를 적고, 관련 문서를 함께 고칩니다.
